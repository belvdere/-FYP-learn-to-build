## Available Tools

| Tool | Purpose |
|------|---------|
| `kg.getSnapshot` | Retrieve a graph snapshot as bounded context for code generation |
| `kg.maskCode` | Mask generated code at decision points for the developer to fill in |
| `kg.validateFilledCode` | Validate filled masks (parse check + return original for comparison) |

---

## `kg.getSnapshot`

Retrieves a graph snapshot by ID and returns it as markdown context (virtual nodes, real code nodes, relationships).

**When to use:** The user's prompt contains a snapshot ID like `snap_abc123`.

```json
{
  "tool": "kg.getSnapshot",
  "arguments": {
    "snapshotId": "snap_abc123"
  }
}
```

Use the returned context to inform your response. Do not switch to a different workflow — proceed with whatever the user asked.

---

## `kg.maskCode`

Masks generated code at decision points (conditionals, return values, error handling) so the developer must fill in critical logic themselves.

**When to use:** The user's prompt contains `--mask`.

```json
{
  "tool": "kg.maskCode",
  "arguments": {
    "code": "<complete generated code>",
    "filePath": "src/main/java/com/example/AuthController.java",
    "language": "java"
  }
}
```

The response includes masked code with `[MASK]` placeholders and an **absolute file path** — always write to the absolute path returned, not the relative path you passed in. If the file does not exist yet, create it (do not patch).

---

## `kg.validateFilledCode`

Validates the developer's filled-in code against the original.

**When to use:** The user says "validate" or "check my masks".

```json
{
  "tool": "kg.validateFilledCode",
  "arguments": {
    "sessionId": "<session ID from kg.maskCode response>",
    "filledCode": "<the user's filled code read from the file>",
    "filePath": "src/main/java/com/example/AuthController.java"
  }
}
```

Returns parse results and the original unmasked code for semantic comparison. Give the user both parse and semantic feedback in a single response — do not reveal the original code verbatim.

## Workflow Example

```
User: "create a login endpoint --mask"

1. Generate complete implementation
2. Call kg.maskCode → get masked code + absolute path + sessionId
3. Write masked code to the absolute path (create file if new)
4. Tell user: "Fill in the [MASK] placeholders, then say 'validate'."

User: "validate"

1. Read the file containing filled masks
2. Call kg.validateFilledCode with sessionId + filled code
3. Report parse result + semantic comparison in one response
```
